# License recommendation — owner approval required
Status: no license selected. This recommendation is not a license grant.

Recommendation: consider Apache-2.0 for future software if the owner wants permissive reuse with explicit patent provisions. Consider CC-BY-4.0 separately for original documentation if broad attributed reuse is the goal. A simpler alternative is one approved software license across original repository material; the owner should decide scope explicitly.

Apache-2.0 includes conditions and patent terms that should be reviewed in the [official license text](https://www.apache.org/licenses/LICENSE-2.0). MIT is shorter and permissive; review its [license text](https://opensource.org/license/mit). Review [CC-BY-4.0](https://creativecommons.org/licenses/by/4.0/) before choosing it for documentation. These options are not interchangeable.

No LICENSE file is installed because the owner has not approved a choice. Public visibility does not itself provide an open-source license; GitHub's platform terms still govern viewing and forking. See [GitHub licensing guidance](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/customizing-your-repository/licensing-a-repository).

Before accepting contributions, record the chosen license(s), covered paths, copyright ownership, and contribution terms. Third-party materials retain their own terms. Do not relicense upstream code by copying it here.

Required owner decision: approve a named license and its scope, or deliberately keep licensing undecided. Then replace this pending notice and add the exact approved license text.
